## HTML

HTML stands for `HyperText Markup Language`. It's the standard markup language for documents designed to be displayed in a web browser. HTML describes the structure of a web page semantically and it consists of a series of elements. These elements tell the browser how to display the content. Elements are represented by tags, such as `<h1>`, `<p>`, `<div>`, `<img>`, etc. You'll learn all about tags and the structure of an HTML page very soon. So the role of HTML is content and structure.

## CSS

CSS stands for `Cascading Style Sheets`. It's a style sheet language used for describing the presentation of a document written in HTML. CSS describes how elements should be styled and rendered on screen. You can do everything from colors, fonts, spacing, layout, and much more with CSS. You can even create really complex animations and transitions with CSS. So the role of CSS is presentation and styling.

## JS

This course is focused on HTML and CSS, but we mide as well talk a little bit about JavaScript. JavaScript is a programming language and can be used to make your webpages dynamic and interactive. When you have websites that have buttons you click or sliders or any interactive elements, that's usually JavaScript. Things like modals, popups and form validation are controlled by JavaScript. We calso dynamically add and remove CSS classes from within JavaScript and we'll be doing some of that later. So the role of JavaScript is behavior and interactivity.

I've always this image because it sums the 3 roles up perfectly. HTML is the skeleton that makes up the structure. JavaScript is the actual functionality so comparable to something like the circulartory system. Then CSS is the presentation and physical appearance.

## Renders on the Client

I want to talk a little bit more about client vs server. HTML, CSS and JS are client-side technologies. This means that they are rendered on the client's machine and browser. When you go to a website, the HTML file is downloaded to your computer along with any CSS and other resources and then rendered by the browser. This is why you can right-click on a web page and view the source code. You're looking at the HTML file that was downloaded to your computer. You aren't accessing the server or anything like that. You can't view the code on the server.

## Server-Side Programming

When you go to a website like Amazon, you're not just downloading an HTML file. You're downloading an HTML file that was generated by a server-side programming language or you're viewing a client side file that makes requests to the server's API for specific data, usually returned in a format called JSON. 

When you look at websites like Amazon and Facebook, these are web applications that have a lot of functionality such as authentication, shopping carts, profiles, messaging. All this stuff is not possible with client-side technologies. You need a server that is running a server-side language such as PHP, Python, C# or even javaScript because JavaScript can run on the server by using a runtime like Node.js. 

These server-side languages also have access to a database. This is where data like the users that registered or the products or blog posts are stored. You can't access a database from the client-side also called the front-end.

If we're strictly using client-side technologies such as HTML & CSS, we can create any kind of informational site and styling it how we want. In fact, you could create a website like Amazon with just HTML and CSS, however, it wouldn't have the functionality. It would just be the interface. You need the server programming for the functionality.

Now, it's important to know that even when you get into server-side programming with something like PHP, Node.js or Python, you'll still be using HTML in some kind of template and you'll still be styling everything with CSS. So it's not like you learn HTML and CSS and then move on. It's something you'll use for your entire career as a web developer. 

I know that's a lot to take in, but I want you to understand the roles of all these different technologies before we move further.
